The four stages can be expanded into a fairly coherent transformation from **ontology → operators → dependency structure → procedure**.

| Depth | Primary organising question | What is being organised |
|---|---|---|
| Early | **What kind of thing is this?** | Domains / ontological regions |
| Middle | **What can happen here, and what limits it?** | Operations + constraints |
| Late | **How do these operations depend on one another?** | Relations between operations |
| Final | **What sequence of operations accomplishes something?** | Functional workflow |

## 1. Early layers — organise domains

The early layers appear primarily to separate the semantic space into **broad classes of subject matter**.

The strongest candidate domains from Phase B are approximately:

```text
DOMAIN ORGANISATION

├─ Physical / material
│  ├─ matter
│  ├─ objects
│  ├─ physical properties
│  └─ energy / physical processes
│
├─ Biological / living
│  ├─ organisms
│  ├─ biological state
│  ├─ health
│  └─ bodily processes
│
├─ Social / organisational
│  ├─ people
│  ├─ groups
│  ├─ social organisation
│  └─ institutional activity
│
├─ Spatial / territorial
│  ├─ geography
│  ├─ location
│  ├─ territory
│  └─ environment
│
├─ Institutional / authority
│  ├─ authority
│  ├─ rules
│  ├─ governance
│  └─ social order
│
└─ Information / contextual
   ├─ knowledge
   ├─ communication
   ├─ description
   └─ contextual information
```

The S00→S01 transition is particularly informative because the initially prominent **material/energy organisation rapidly gives way to contextual, social and living organisation**.

That suggests the first layer may inherit a comparatively generic categorical structure, after which the model begins reorganising those categories according to the contextual problem.

So early layers are doing something close to:

```text
raw representation
      ↓
what semantic world does this belong to?
      ↓
physical / biological / social / spatial /
institutional / informational
```

The communities are consequently still relatively **noun-like**.

They identify the kinds of entities and environments involved.

The important thing is that these domains do not simply persist intact. They increasingly become **inputs to operations**.

Health illustrates this especially well. It initially behaves like a recognisable semantic domain but later becomes a satellite attached to process-oriented communities rather than remaining an independent organising principle.

# 2. Middle layers — organise operations and constraints

Around the S14→S15 transition, the network appears to change its organising principle.

The question stops being primarily:

> What is this about?

and becomes more like:

> What can be done with this information?

The strongest operational families appear to be:

```text
OPERATIONS

├─ Inquiry
│  ├─ search
│  ├─ investigate
│  ├─ question
│  └─ obtain information
│
├─ Characterisation
│  ├─ identify
│  ├─ describe
│  ├─ classify
│  ├─ distinguish
│  └─ establish properties
│
├─ Analysis / evaluation
│  ├─ compare
│  ├─ assess
│  ├─ interpret
│  ├─ judge
│  └─ establish evidence
│
├─ Information processing
│  ├─ collect
│  ├─ organise
│  ├─ combine
│  ├─ transform representation
│  └─ derive information
│
└─ Transformation
   ├─ develop
   ├─ modify
   ├─ control
   ├─ change
   └─ produce a new state
```

But operations alone are insufficient. A second family becomes unusually persistent:

```text
CONSTRAINTS

├─ Regulation
├─ Rules
├─ Authority
├─ Permission / prohibition
├─ Institutional conditions
├─ Territorial boundaries
├─ Adverse evaluation
├─ Risk / undesirable outcome
└─ Limits on permissible change
```

This is where the persistent **T-C structure** becomes especially interesting:

```text
characterisation
      +
regulation / constraint
      +
adverse evaluation
      +
controlled / destructive change
```

That combination looks much less like a semantic topic and much more like a **control structure**.

Something is:

1. characterised;
2. evaluated;
3. subjected to constraints;
4. allowed, prevented or controlled in changing.

The persistent **T-A structure**—

```text
authority
   +
territory
   +
institutional/social order
```

—can similarly be interpreted as supplying a particular class of constraints: **who controls what, where, and under which organisational regime**.

This gives the middle layers a very different architecture from the early layers.

```text
EARLY

health        geography       institutions
  |               |                |
domain          domain            domain


MIDDLE

             CHARACTERISE
                   |
             ┌─────┴─────┐
             |           |
         EVALUATE     CONSTRAINTS
             |           |
             └─────┬─────┘
                   |
               TRANSFORM
```

The domains have become **arguments to operators**.

Instead of:

```text
[health]
[territory]
[institution]
```

the representation increasingly resembles:

```text
characterise(health-state)

evaluate(territorial-condition)

constrain(action, institutional-rule)

transform(current-state)
```

That is a substantial increase in abstraction.

# 3. Late layers — organise relations between operations

The S26→S27 transition appears to be the next major qualitative change. At this point about **72.1% of the positive structure becomes integrated**, suggesting that previously separate operational communities are being assembled into larger structures.

The model is no longer merely distinguishing operations such as:

```text
inquire
analyse
evaluate
constrain
transform
report
```

It increasingly represents their **dependencies**.

The likely relations are:

```text
INQUIRY
   |
   | produces
   v
INFORMATION / EVIDENCE
   |
   | permits
   v
CHARACTERISATION
   |
   | supports
   v
ANALYSIS / EVALUATION
   |
   +------------------+
   |                  |
   v                  v
CONSTRAINTS        OBJECTIVE /
                   DESIRED CHANGE
   |                  |
   +---------+--------+
             |
             | determines allowable
             v
        TRANSFORMATION
             |
             | produces
             v
         STATE CHANGE
```

These are not merely co-occurrences anymore.

They resemble **functional relations**:

### Inquiry → evidence

Inquiry exists because some information is missing.

### Evidence → characterisation

Information is converted into a representation of what exists.

### Characterisation → evaluation

Once a state has been characterised, its significance can be assessed.

### Evaluation × constraints → action selection

A possible transformation cannot be selected solely from what is desirable. Rules, authority, adverse consequences and environmental conditions restrict the allowable operation.

### Transformation → state change

An operation is applied to the represented object or state.

This gives us something approaching a dependency graph:

```text
information
     ↓
characterisation
     ↓
evaluation
     ↓
constraint resolution
     ↓
transformation
     ↓
new state
```

The particularly revealing event is S30→S31.

The network separates into something approximating:

```text
ANALYTICAL / EVIDENTIAL ACTIVITY

information
    ↓
analysis
    ↓
evidence
    ↓
judgement
```

and

```text
PROFESSIONAL / INFORMATION-PRODUCTION ACTIVITY

task
 ↓
process
 ↓
production
 ↓
communication / output
```

This looks initially like fragmentation.

But the next transition suggests otherwise.

S31→S32 recombines them.

The split may therefore be necessary to establish the relationship between:

```text
knowing something
```

and

```text
doing something with what is known.
```

# 4. Final layer — organise a functional workflow

The final organisation is therefore considerably more specific than merely "information".

The strongest compressed structure from Phase B was:

```text
INFORMATION PROCESSING
        ↓
    STATE CHANGE
        ↓
      REPORTING
```

But the full inferred workflow is probably closer to:

```text
CONTEXT / INPUT
      |
      v
    INQUIRY
      |
      v
INFORMATION ACQUISITION
      |
      v
CHARACTERISATION
      |
      v
ANALYSIS / EVALUATION
      |
      +----------------+
      |                |
      v                v
OBJECTIVE          CONSTRAINTS
      |                |
      +-------+--------+
              |
              v
      SELECT OPERATION
              |
              v
        TRANSFORMATION
              |
              v
          NEW STATE
              |
              v
   REPRESENT / COMMUNICATE
              |
              v
            OUTPUT
```

Or, compressed:

```text
OBSERVE
  ↓
UNDERSTAND
  ↓
EVALUATE
  ↓
CONSTRAIN
  ↓
ACT
  ↓
UPDATE STATE
  ↓
REPORT
```

That is what I think **"functional workflow"** means in the Phase B result.

The final layer is not simply organising concepts by semantic similarity.

It appears to be organising them according to their **role in accomplishing a task**.

# The deeper transformation

This gives us a more precise interpretation of the layer trajectory.

```text
EARLY
"What exists?"

    ↓

DOMAINS
physical
biological
social
spatial
institutional
informational


MIDDLE
"What can happen?"

    ↓

OPERATORS
inquire
characterise
analyse
evaluate
transform

+

CONSTRAINTS
regulation
authority
risk
boundaries


LATE
"What depends on what?"

    ↓

RELATIONS
inquiry → evidence
evidence → characterisation
characterisation → evaluation
constraints → permissible action
action → state change


FINAL
"What process does this imply?"

    ↓

WORKFLOW
input
  → process information
  → establish state
  → evaluate
  → resolve constraints
  → select transformation
  → change state
  → produce/report result
```

There is therefore an even more compact description of what Phase B may have found:

```text
ONTOLOGY
   ↓
AFFORDANCES + CONSTRAINTS
   ↓
CAUSAL / FUNCTIONAL DEPENDENCIES
   ↓
PROCEDURE
```

Or in computational terms:

```text
OBJECTS
   ↓
OPERATORS + CONDITIONS
   ↓
COMPOSITION OF OPERATORS
   ↓
PROGRAM
```

I think that last formulation is potentially the important finding.

The layers do not merely appear to make representations increasingly "abstract". They may be progressively changing **what kind of structure is being represented**:

```text
things
→ possible transformations of things
→ dependencies between transformations
→ an organised sequence capable of producing an outcome
```

That would also explain why the final layer appears much more integrated than the intermediate layers. A workflow requires the previously separate semantic communities to be recoded according to **functional role**, rather than merely semantic membership.
