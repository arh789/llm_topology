R012 now gives a fairly complete answer to two questions at once: what the whole-prompt topology pipeline needs technically, and what is wrong with using an instruction-bearing response position as the default measurement for SDA-style semantic neighbourhood analysis. R013 should preserve the first result and correct the second.

# R012 Synthesis and Implications for R013

## 1. What R012 was actually for

R011 was intended to establish a generalised pipeline capable of accepting different models and measuring the layer-wise semantic topology of a complete prompt.

R011 failed because the selected quantised CPU runtimes could not expose the required intermediate hidden states. The failure was an instrumentation problem, not evidence that the overall method or large-system-RAM approach was infeasible.

R012 therefore existed to correct the model/runtime choice and complete the pipeline originally intended by R011.

Its correct architecture became:

```text id="h5emur"
MODEL / RUNTIME
      ↓
CAPTURE FINAL-POSITION HIDDEN STATE
AT EVERY TRANSFORMER DEPTH
      ↓
PROJECT EACH STATE AGAINST
THE MODEL'S INPUT-EMBEDDING VOCABULARY
      ↓
SELECT POSITIVE / NEGATIVE REGIONS
      ↓
CONSTRUCT TOKEN NETWORKS
      ↓
DETECT COMMUNITIES
      ↓
COMPARE THROUGH DEPTH
      ↓
COMPARE CONTROLLED PROMPTS
      ↓
EXPORT CHATGPT-READABLE EVIDENCE
      ↓
STOP BEFORE SEMANTIC INTERPRETATION
```

The initial capture-only interpretation of R012 was therefore incomplete. R012 was reopened and completed rather than spawning another run.

---

# 2. What R012 technically established

R012 validated the complete measured pipeline using Qwen2.5-7B-Instruct in BF16.

The controlled prompts were:

```text id="qxpa37"
BASELINE
What structure forms from electro pink, curvature density, Tokyo nightlife?

VARIATION
What structure forms from electro pink, Tokyo nightlife, curvature density?
```

Only the order of `curvature density` and `Tokyo nightlife` changed.

No response token was generated.

The measured position was the fixed final assistant-prefix position supplied by Qwen's official chat template.

The 7B capture produced:

```text id="z01prz"
29 states
=
input embedding
+
28 transformer outputs / terminal representation
```

with hidden width:

```text id="5i49w8"
3584
```

State 00 was exactly identical across the two prompts because the measured input token was identical before attention had incorporated the preceding context.

Every subsequent state differed.

This proved that a small ordering change in the concepts propagates through the entire whole-prompt representation.

R012 then reused the established R004 full-curve elbow method independently for positive and negative populations.

# 4. What R012 demonstrated about prompt-order sensitivity

The perturbation begins small.

At State 01:

```text id="wf524i"
average membership overlap ≈ .955
average edge overlap       ≈ .884
```

The model is initially processing almost the same semantic material.

The difference becomes progressively larger.

By the final transformer region:

```text id="5gdhun"
S27

positive membership Jaccard ≈ .821
negative membership Jaccard ≈ .822

positive edge Jaccard ≈ .632
negative edge Jaccard ≈ .637
```

This means that merely reversing two concept phrases leaves most of the selected vocabulary in common, but substantially changes the relational network connecting those tokens.

The important distinction is:

```text id="zldb35"
TOKEN MEMBERSHIP
relatively stable

RELATIONAL STRUCTURE
less stable

COMMUNITY PARTITION
even less stable
```

This is especially visible at State 17:

```text id="webtge"
average membership ≈ .851
average edge overlap ≈ .684
average community ARI ≈ .366
```

The two prompts therefore contain largely similar semantic ingredients and many similar relations, yet organise them into substantially different communities.

That is evidence for:

```text id="iduior"
SAME SUBSTRATE
      ↓
DIFFERENT COMPRESSION
      ↓
DIFFERENT PARENT BOUNDARIES
```

rather than simple replacement of one semantic neighbourhood by another.

# 5. The principal developmental trajectory

R012 broadly reproduces one of the strongest findings from R010.

The model does not preserve the concepts as three intact topical blocks.

Instead the representation moves through approximately:

```text id="y2fhs2"
LEXICAL / OBJECT ASSOCIATIONS
        ↓
FEATURES AND PROPERTIES
        ↓
OPERATIONS
        ↓
RELATIONS BETWEEN FEATURES AND OPERATIONS
        ↓
HIGHER-ORDER COMPOSITION
```

The most defensible epochs are:

```text id="pe0oww"
S00
FIXED CAPTURE ANCHOR
│
▼
S01–05
CONTEXT ACQUISITION
│
│ lexical, object, action and formal activation
▼
S06–09
FEATURE ASSEMBLY
│
│ material, physical and spatial properties
▼
S10–18
RELATIONAL ORGANISATION
│
│ environment, representation,
│ transformation and social context
▼
S19–23
COMPOSITION
│

S24–27

│
│ increasingly stable parent inventory,
│ continuing repartition of communities
▼
S28
TERMINAL NORMALISATION / RECODING
```

The recurring pattern is therefore again:

```text id="jhcw8d"
OBJECTS
→ ATTRIBUTES / OPERATORS
→ RELATIONS
→ FUNCTIONAL OR COMPOSITIONAL STRUCTURE
```

# 7. The resulting semantic structure

Across both prompt orderings, the smallest defensible higher-order architecture is approximately:

```text id="7b0dli"
SEMANTIC INTERSECTION
│
├── MATERIAL / SENSORY FIELD
│
├── SPATIAL / ENVIRONMENTAL FIELD
│
├── TRANSFORMATION / COMPOSITION
│
├── REPRESENTATION / INFORMATION
│
└── SOCIAL / INSTITUTIONAL CONTEXT
```

Their relations are more informative than the labels themselves:

```text id="xyffl5"
MATERIAL / SENSORY FEATURES
            │
            │ situated within
            ▼
SPATIAL / ENVIRONMENTAL CONTEXT
            │
            │ organised through
            ▼
TRANSFORMATION / COMPOSITION
            │
            │ expressed through
            ▼
REPRESENTATION
            │
            │ embedded within
            ▼
SOCIAL / INSTITUTIONAL CONTEXT
```

The model therefore does not strongly encode the intersection as a named aesthetic genre.

The stronger interpretation is:

> A constructed sensory-spatial environment in which material and perceptual properties are transformed into compositional form and represented within a situated social or urban context.

# 9. Order-invariant versus order-sensitive meaning

This is R012's strongest experimental contribution.

The higher-order parent inventory is substantially more stable than the token and community structures.

Both prompts repeatedly recover:

```text id="96fvgn"
transformation / composition
material / sensory organisation
representation
spatial / place context
social / institutional context
```

What changes with concept order is primarily:

```text id="pk4qg1"
which communities are grouped together

which parent absorbs a community

how autonomous the spatial/place branch remains

whether social activity is integrated with sensory/material structure

how representational structures are compressed

where peripheral associations fall
```

Therefore:

> Parent identity is more stable than community identity.

And:

> Relations between parents appear more invariant than the exact token neighbourhood from which those parents are reconstructed.

This directly strengthens the parent-node direction developed from R010.

# 12. State 28 changes how terminal states must be interpreted

State 28 is not another transformer block.

It is the final normalisation state.

The S27→S28 transition is enormous:

```text id="u2ebgw"
membership Jaccard ≈ .129
edge Jaccard       ≈ .026
```

Therefore:

```text id="v36ppz"
S27
last transformer-computed representational organisation

        ↓

final normalisation

        ↓

S28
terminal vocabulary-space recoding
```

The semantic content of S28 is useful because it is close to what the output head receives.

But it must not be interpreted as another semantic reasoning step.

Future pipelines should explicitly distinguish:

```text id="j1paic"
LAST BLOCK STATE
from
POST-NORMALISATION STATE
```

rather than treating both as equivalent transformer layers.

# 13. What R012 means for SDA-3 / GRD

R012 strongly supports the hierarchy:

```text id="5d5yxa"
TOKENS
least stable
        ↓
COMMUNITIES
more stable but plastic
        ↓
PARENT STRUCTURES
substantially more stable
        ↓
RELATIONS BETWEEN PARENTS
strongest candidate for persistent semantic structure
```

So SDA/GRD should operate after parent reconstruction:

```text id="j4wf20"
MEASURED TOKEN NEIGHBOURHOOD
        ↓
COMMUNITIES
        ↓
PARENT RECONSTRUCTION
        ↓
PARENT RELATIONS
        ↓
STABILITY UNDER PERTURBATION
        ↓
GRD ROLES
        ↓
MINIMAL GENERATIVE STRUCTURE
```

not:

```text id="vtaa8k"
tokens
→ assign C / S / A / HCU / E
```

The controlled perturbation is important because it provides empirical evidence for this hierarchy.

A substantial fraction of the token network can change while the same higher-order parent structure remains recoverable.

# 14. The central experimental limitation exposed by R012

R012 measures the hidden state of a fixed assistant-generation prefix in an instruction-tuned model.

Therefore the measured state contains:

```text id="luftaz"
A/B/C semantic contribution
+
"What structure forms from" contribution
+
chat-template contribution
+
instruction-following behaviour
+
response-preparation contribution
+
concept-order interaction
```

This explains why R012 contains large amounts of:

```text id="id4b6s"
code
punctuation
multilingual morphology
formatting
generic response operators
```

alongside genuine semantic structure.

The pipeline is valid.

The measurement target is simply broader than SDA-3 originally required.

# 15. The specific prompt-shell confound

The largest example is:

```text id="7p1gx6"
transform / form / composition
```

This looks like a strong semantic lineage.

But the instruction itself asks:

```text id="9x5nea"
What structure forms from ...
```

Therefore R012 cannot determine whether:

```text id="pel457"
transform / form
```

is:

```text id="d3gta0"
intrinsic to
electro pink + curvature density + Tokyo nightlife
```

or partly caused by:

```text id="ickoqo"
structure + forms
```

in the shell.

R013 should remove this ambiguity.

# 16. R013 should change the experimental question

R012 asked:

> How does an instruction-tuned model organise an entire synthesis prompt immediately before answering?

R013 should ask:

> What semantic topology is induced by the concepts themselves when they co-occur?

The minimal input should therefore be approximately:

```text id="hw9v0z"
electro pink | curvature density | Tokyo nightlife |
```

with the final fixed delimiter used as the measurement anchor.

Conceptually:

```text id="drccka"
A
B
C
↓
NEUTRAL FIXED ANCHOR
↓
layer-wise contextual state
```

This removes:

```text id="z8m8ah"
"What structure forms from"
```

as a semantic input.

---

# 17. Why a fixed anchor remains necessary

R013 should not simply measure the final concept token.

For:

```text id="wxoarb"
electro pink, curvature density, Tokyo nightlife
                                      ↑
```

`nightlife` would simultaneously be:

```text id="bc72wv"
one of the concepts
+
the measurement anchor
```

which reintroduces the asymmetry seen in R010.

Instead:

```text id="n3g5z6"
electro pink | curvature density | Tokyo nightlife |
                                                   ↑
                                             fixed anchor
```

The same anchor should be used for every permutation.

---

# 18. R013 should test all six permutations

R012 only compared:

```text id="holnpu"
A B C
A C B
```

That cannot separate:

```text id="gf02oi"
order effects
recency effects
adjacency effects
specific B–C interaction
```

R013 should use:

```text id="yd2rr5"
A B C
A C B
B A C
B C A
C A B
C B A
```

with identical separators and identical capture rules.

Then the topology can be decomposed into:

```text id="zrrb5m"
ORDER-INVARIANT CORE
structures surviving all six permutations

RECENCY EFFECT
structures systematically associated with the last concept

POSITION EFFECT
structures associated with first / middle / final placement

ADJACENCY EFFECT
structures strengthened when two concepts are neighbouring

INTERACTION EFFECT
changes not explainable by position alone
```

This is considerably more informative than another two-prompt comparison.

# 20. Base model versus instruct model

If the purpose of R013 is semantic topology rather than chatbot behaviour, a base causal model is methodologically cleaner.

Instruction model:

```text id="48788j"
concepts
+
chat template
+
instruction tuning
+
assistant prefix
```

Base model:

```text id="1s5ccp"
concepts
+
fixed delimiter
```

The base model therefore better isolates ordinary contextual semantic integration.

However, model comparison should remain controlled.

The most defensible sequence would be:

```text id="020daw"
first:
same Qwen family / architecture where possible
to isolate the prompt-design change

then:
base versus instruct comparison
as a separate variable
```

Changing prompt design and model training regime simultaneously would make attribution harder.

# 21. What R013 should preserve unchanged

R012's downstream measurement machinery is now sufficiently validated.

R013 should preserve, unless evidence forces a change:

```text id="l5yo08"
hidden-state capture contract

static input-embedding projection

full-curve positive / negative elbow method

exact within-side 10-NN graphs

deterministic Louvain communities

community-level exports

adjacent-state comparisons

matched-prompt comparisons

ChatGPT-readable JSON / Markdown evidence

strict separation of measurement and interpretation
```

R013 is therefore not a new topology pipeline.

It is a cleaner experimental input design using the established pipeline.

# 22. What should become model-general

The reusable backend contract remains:

```text id="76kwb9"
capture_states(prompt)

get_embedding_matrix()

get_vocabulary()

get_state_labels()

get_model_metadata()
```

Everything downstream should consume those common objects rather than Qwen-specific internals.

R012 validated the abstraction with one backend.

R013 should avoid expanding into a large adapter framework unless another model is actually being tested.

Generalisation should remain empirical rather than speculative.

---

# 23. Proposed R013 objective

A suitable objective is:

> Measure the layer-wise semantic topology induced by a fixed set of concepts without an explicit synthesis instruction, and determine which token, community, parent and relational structures remain invariant under all permutations of concept order.

This gives R013 three primary questions:

```text id="aftd9g"
1. What semantic structure emerges from A, B and C
   without instructing the model what relation to construct?

2. Which parts of that structure survive all concept orders?

3. Which changes are attributable to position, recency,
   adjacency or higher-order interaction?
```

# 25. What success in R013 would mean

R013 would be successful if it lets us make a substantially stronger claim than R012:

R012 supports:

> Higher-order semantic parents survive a limited concept-order perturbation better than tokens or communities.

R013 could establish:

> A specific parent-and-relation structure remains recoverable across the complete permutation space of the same semantic inputs, making it a credible candidate for the model's order-independent representation of that conceptual intersection.

That would move the project from:

```text id="vw66u7"
semantic reconstruction
```

towards:

```text id="upeuk3"
semantic invariant identification
```

which is much closer to the original purpose of SDA-3.

## Central conclusion

R012 succeeded technically and analytically, but it also demonstrated that the whole-prompt assistant-prefix state is broader than the semantic object SDA-3 originally sought.

Its strongest substantive result is:

> **Semantic invariance appears to increase with abstraction: tokens are highly plastic, communities are moderately plastic, parent structures are substantially more stable, and relations between parents are the strongest candidate for the model's persistent representation of a conceptual intersection.**

Its strongest methodological result is:

> **To test that claim cleanly, R013 should remove the semantic instruction shell, use a fixed neutral anchor, run every permutation of the same concept set, preserve the validated R012 topology pipeline, and identify which parent relations survive all ordering changes.**
