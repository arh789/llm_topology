R017 successful measurement

Choke point + collapsible barrier + spear

A layer-wise semantic map generated from one native-BF16 forward pass through allenai/Olmo-3-1125-32B.

Strongest supported result

The three inputs form a tactical interception architecture: a constrained passage channels movement; a deployable obstruction shapes or blocks that flow; and a reach/piercing weapon supplies force at the resulting point of contact.

The model does not preserve the input merely as three neighbouring nouns. It first resolves spear concretely as a weapon, blade and piercing object. Through later depth, that object-level neighbourhood loses independence while the relational structure becomes more prominent: point, intersection, narrow, flow, movement, folding, blocking, deploy, collapse, attack, guard, wall, restriction, channel and route.

The resulting structure is therefore less “a spear beside a barrier at a choke point” and more:

force movement through a constrained place
                  ↓
deploy an obstruction that controls the passage
                  ↓
exploit the narrowed approach with reach / piercing force

Sector asymmetry

The positive side progressively carries the active procedure: weapon use, blocking, folding, movement, deployment, intersection, attack and guards. The negative side progressively carries the spatial and limiting counterpart: path/exit, access, walls, restriction, channel, defence and route.

This does not establish that the model suppresses walls, defence or routes. It establishes geometric anti-alignment in the fixed input-embedding basis. Functionally, however, the paired sectors distinguish what acts from what bounds the action.

Evidence and limitations

  • This is a single prompt in a single order. Unlike R014/R015, it does not establish order, context or neighbouring-concept invariance.
  • The parent map is reconstructed after measurement. Parent names are not direct model outputs.
  • Intercommunity edges exist only within one state and cosine sector. Repeated parent identity across sectors is interpretive; no positive-to-negative graph edge was measured.
  • Many large OLMo communities are lexical, multilingual, formatting, code or named-entity structures. Prompt-specific meaning is often clearest in target-extreme tokens and persistent trajectories rather than the largest community by size.
  • State 00 is the uncontextualised newline embedding. State 64 combines Block 63 output with final normalisation. Neither should be treated as an ordinary middle layer.
  • The method measures a model-mediated semantic topology learned from training data, not a direct inventory of raw training documents.

Report standardisation candidates

R014/R015 and this run now point to a stable minimum report schema. Standardisation should preserve these fields without forcing every experiment into the same comparison design:

  1. Run identity: model, exact revision, prompt set, capture position, state definition and generation status.
  2. Completeness: expected versus observed states, networks, transitions, memberships, edges and communities.
  3. Strongest supported result: one plain-language statement, separated from caveats.
  4. Prompt decomposition: each input concept → recovered components → exact evidence.
  5. Depth development: a small number of evidence-led phases, with state boundaries stated rather than presumed.
  6. Parent table: identity, contents, sector/depth tendency, evidence and confidence.
  7. Relation table: endpoints, relation, measured support, interpretive status and confidence.
  8. Semantic map: one compact diagram showing only supported parents and relations.
  9. Sector boundary: explicit reminder that negative cosine is anti-alignment, not automatic suppression.
  10. Invariance status: clearly state whether order, context, neighbouring concepts or models were perturbed—or not tested.
  11. Limitations and artefacts: tokenizer/formatting structure, capture boundary, and any model-specific effects.
  12. Primary records: direct links or paths to manifest, measured packets, community exports and completeness verification.

The schema should distinguish a single-trajectory semantic-map report such as R017 from a cross-perturbation invariance report such as R014/R015. The common core can be standardised; comparison-only sections should remain conditional.

Conclusion

For OLMo 3 32B Base, “choke point + collapsible barrier + spear” generates a semantic map of controlled passage and tactical interception: spatial restriction makes movement predictable, a deployable obstruction shapes the approach, and reach/piercing force acts at the resulting point of contact.
